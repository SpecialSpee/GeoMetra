### 1.2 Логические баги (тихие, но убивают обучение)

1. **`performance.now() / 60000` — это время от загрузки страницы, не от старта матча.** После рестарта ИИ сразу «на 15-й минуте» и получает все late-штрафы с первого тика. Нужен `gameStartTime` или игровой таймер (и вычитать паузы).
2. **`this.lastResourceTotal` никогда не обновлялся** → проверка прироста ресурсов мертва всегда.
3. **`hasBase2 = b.active`** → строящаяся база не считается. ИИ наказан за правильное действие.
4. **`totalArmy = units.length` включал воркеров** → `fighterRatio`, «разнообразие армии», `turrets_without_army` считались по мусору. 10 воркеров + 2 элиты = «90% не-фантомов»… точнее, наоборот: composition-бонусы не срабатывали вообще.
5. **Двойной/тройной счёт:** `no_barracks` ×2, `no_base2` ×2, `no_workers` ×3, `turrets_without_army` ×2.
6. **Reward drowning:** `-5 * minutesLate` без предела. На 20-й минуте один `no_base2` = **-70 каждые 10 секунд**, и градиент от побед/урона просто тонет. Модель учится только «лишь бы не орало в консоль».
7. **Кредит-ассайнмент:** всё пишется как `AIDX.idle`. Модель выучивает «idle плохо», а не «не построил Base2 плохо». Нужно винить конкретное упущенное действие (в фиксе — по самому дорогому штрафу).
8. **Нет терминального перехода.** После смерти ИИ штрафы продолжают литься в буфер, портя статистику матчей, которых уже нет.
9. **Штраф не нормирован по `dt`.** При лаге/свернутой вкладке интервал 30 с, а штраф как за 10 с.
10. `penalty` — имя, в котором лежат и награды. Мелочь, но путает при отладке.

## 2. Архитектура награды: главный рычаг играбельности

### 2.1 Как ИИ взломает твои текущие правила (reward hacking)

| Правило | Как модель его обойдёт |
|---|---|
| Штраф за 80% фантомов при `army > 15` | Держать армию ровно 15 юнитов и никогда не расти |
| Бонус за 2–3 типа армии | Купить по 1 юниту каждого типа → +15 «фарма» без реальной силы |
| Штраф за маяки без Base2 | Вообще не строить маяки, даже когда они полезны для vision/расширения |
| Штраф за турели без армии | Не строить турели → голая база, но «нет штрафа» |
| Прогрессивный `no_base2` | Поставить Base2 в первый же тик, даже если это самоубийство по экономике |
| Штраф за 0 воркеров | Один воркер навсегда — формально не ноль |

**Вывод:** наказывай/награждай **исход**, а не прокси-метрику. Прокси — только как слабый, насыщающийся шейпинг.

### 2.2 Правильный шейпинг (potential-based, Ng et al. 1999)

Единственная форма шейпинга, которая **математически не меняет оптимальную политику**:

```
F(s, s') = γ · Φ(s') − Φ(s)
```

Φ — «насколько хороша позиция». Реализация уже есть в фиксе (`potential()` / `shapeReward()`):

```js
Φ(s) = 6·log1p(workers) + 4·log1p(armyValue) + 8·(tier−1)
     + 3·log1p(incomePerMin) + 5·mapControl + 4·dmgDealt/1000 − 4·dmgTaken/1000
```

`log1p` вместо линейных членов = **насыщение**: 20-й воркер не даёт столько же, сколько 3-й. Это само по себе убивает большую часть фарм-стратегий.

Итоговая награда:
```js
r = r_outcome + clip(γΦ(s') − Φ(s), -10, 10) + r_shaping_heuristics * 0.3
```
где `r_outcome` — то, чего сейчас нет вообще:
* `+1.0` за убийство юнита врага (взвешенно по цене), `−1.0` за потерю своего;
* `±0.5` за разницу «нанёс урона / получил урона» за окно 30 с;
* `+3` за уничтоженное здание, `+8` за расширение (новая база на другом ресурсном пятне);
* **терминал: `+100` победа / `−100` поражение**, и всё остальное — на порядок меньше.

### 2.3 Гигиена награды (внедрено в фикс)
* капы по категориям (`eco / army / tech / tempo / bonus`) — один проступок не может съесть весь сигнал;
* мягкий клиппинг `25·tanh(sum/25)` вместо жёсткого — сохраняется градиент;
* нормировка по реальному `dt`;
* вехи (`первый barracks`, `Tier-2`, `6 воркеров`) — **однократно**, а не каждые 10 с;
* сатурация «опоздания»: `min(minutesLate, 5)`.

### 2.4 Что убрать/переписать
* Штраф за состав армии → замени на **эффективную стоимость армии** (`armyValue`) и на «army value / army cost» после боя. Состав — это следствие, а не цель.
* Штраф за турели → замени на **`mapControl` + `damageTaken`**: пассивная игра сама станет невыгодной, потому что враг заберёт карту.
* Три worker-штрафа → один + насыщающийся бонус за `log1p(workers)`.

## 3. Апгрейд самой модели (по соотношению эффект/усилия)

### 🥇 Приоритет 1 — делается за вечер, эффект огромный

**1. Action masking.** Самое дешёвое ускорение сходимости в RTS. Нельзя строить — минус бесконечный Q, а не «пусть научится».
```js
const mask = getLegalActionMask();           // bool[|A|]: хватает ресурсов, есть тех-требования, есть место
const q = model(state);
for (let i = 0; i < q.length; i++) if (!mask[i]) q[i] = -1e9;
```
Модель перестаёт тратить 80% эпизодов на «попробую построить Base3 без Base2».

**2. Behavior cloning warm start.** 20–50 матчей скриптового бота (или своих рук) → обучение с учителем на 2–3 эпохи → потом RL. ИИ становится **играбельным сразу**, а не через 5000 матчей случайных тыков.
```js
loss = CrossEntropy(policy(state), scriptedAction)   // фаза 1
loss = TD_loss + 0.1 * CE_demo                       // фаза 2, демо-регуляризатор
```

**3. epsilon/entropy по расписанию + floor.** `ε: 0.9 → 0.05` за N матчей, но **никогда не 0** — иначе ИИ застывает в одной стратегии и становится скучным.

**4. Нормировка входов GNN.** Расстояние / 1000, ресурсы / 2000, HP в 0..1, one-hot типа. Без этого первые слои «слепнут» на больших числах. Логи проверь: если `X` содержит сырые пиксели координат — это половина проблем.

### 🥈 Приоритет 2 — стабильность и качество

**5. n-step returns (n=3..5) + приоритизированный реплей.** Сейчас буфер, судя по `{X, A_distance, A_threat, actionIndex, reward}`, хранит одношаговые переходы без `s'` и `done`. Добавь `X_next`, `done`, `tdError` → PER с `α=0.6, β=0.4→1`. Победа/смерть — редкие события, uniform replay их размывает.

**6. Double + Dueling DQN, target network (soft update τ=0.005), Huber loss.** Убирает переоценку Q (типичная причина «ИИ уверенно делает глупость»).

**7. Reward normalization (PopArt) или running std.** Иначе масштаб наград между ранней и поздней игрой различается в 10 раз.

**8. Рекуррентность / frame stack.** RTS — POMDP (туман войны). GRU(128) после GNN-энкодера или стек 4 последних состояний. Без памяти ИИ не может «помнить, что там враг строил базу».

**9. GNN specifics:**
   * рёбра с признаками: `Δpos`, дистанция, «угрожает/лечит/добывает», принадлежность;
   * 2–3 слоя GATv2 / GraphTransformer с 4 головами (attention сам выучит «кто опасен»);
   * separate node types (unit / building / resource) → hetero-GNN (R-GCN);
   * readout: attention-pooling + отдельный «global token» для ресурсов/тира/времени;
   * **dueling heads:** `V(s)` + `A(s,a)`, где A считается per-node (для «атаковать этот юнит») — иначе комбинаторный взрыв действий.

### 🥉 Приоритет 3 — сила и разнообразие

**10. Self-play лига вместо игры с самим собой.** Пул: 5–8 прошлых чекпоинтов + 3 скриптовых бота (rusher / turtler / boomer). Сэмплируй оппонента по винрейту (приоритет тем, кто тебя бьёт ~50%). Это лечит главный симптом «ИИ выучил одну эксплойт-стратегию и разваливается против любой другой».

**11. Curriculum:** маленькая карта + много ресурсов + слабый враг → нормальная карта → туман войны → сильный враг.

**12. Иерархия (macro / micro).** Верхняя политика раз в 5–10 с выбирает **стратегию** (`expand / army / tech / harass / defend`), нижние исполняют. Даёт читаемое, «осмысленное» поведение вместо дрожащего микро. Плюс отдельный squad-контроллер (отступление при HP<30%, фокус-огонь по слабейшему).

## 4. Как сделать ИИ **интересным**, а не только сильным

Это отдельная задача: сильный ИИ часто = скучный ИИ (одна идеальная сборка каждый матч).

**1. Вектор личности на входе политики.**
```js
style = [aggression, expansion, techGreed, harassment, turtle]  // one-hot или softmax-вектор
policy = model(state, style)
```
Обучай с рандомным `style` + награда за соответствие стилю (доля урона в первые 5 мин, число баз, тир). На старте матча сэмплируй стиль → **каждый матч противник другой**. Дёшево, а вариативность растёт в разы.

**2. Книга дебютов.** 5–10 курируемых билд-ордеров первых 90 секунд, выбор случайный/по стилю. RL берёт управление после дебюта. Убирает «ИИ 2 минуты стоит и думает» — самое частое впечатление «он тупой».

**3. Сэмплирование вместо argmax.** `top-p = 0.9`, температура 0.7–1.2 по стилю. Argmax = детерминированный = предсказуемый = скучный.

**4. Гистерезис/приверженность решению.** `minCommitMs = 8000` на стратегию + гистерезис переключения (порог входа выше порога выхода). Без этого ИИ дёргается между «атакую»/«отступаю» каждые 200 мс и выглядит идиотом, даже если политика хороша. **Это чинит «играбельность» сильнее, чем +10% винрейта.**

**5. Сложность через человека, а не через читы.** Легкий/средний/тяжёлый = задержка реакции (600/300/120 мс), лимит APM (60/120/300), вероятность ошибки/пропуска скана, а не ×2 ресурсов. Чит-бонусы игроки чувствуют и ненавидят.

**6. Разведка и «информационная модель».** ИИ должен строить юнит-разведчик, помнить последние увиденные позиции с таймстемпом и **действовать по неполной информации** (иногда ошибаться). Сейчас `strategicMemory.threatLevel` — плоское число; сделай карту угрозы по секторам + список «видел врага X тут, T секунд назад».

**7. Тайминг-атаки и окна силы.** Награда за атаку в момент преимущества (`armyValue_ratio > 1.3` или только что вышел Tier-2). ИИ начнёт «чувствовать момент» — это то, что игроки называют «он играет как человек».

**8. Comeback-механика.** При отставании >40% — повышать риск-аппетит (температуру, вес агрессии). Иначе проигрывающий ИИ просто досиживает матч в углу, и игроку скучно добивать.

**9. Реплики/телеметрия намерения.** «ИИ строит Tier-2», «ИИ готовит раш» в дебаг-оверлее (или как taunt-сообщения). Понятный противник воспринимается как умный.

## 5. Измеряй, иначе всё выше — гадание

Минимальный harness: 100 матчей против фиксированных ботов на каждый чекпоинт.

| Метрика | Зачем |
|---|---|
| Winrate vs rusher / turtler / boomer | видно, где политика слепая |
| Среднее время до barracks / Base2 / Base3 | тайминги = «здравость» макро |
| Resource float (среднее `resTotal`) | тот самый RICH_FOOL, но как метрика, а не кара |
| Army value / потери | эффективность боёв |
| Уникальных билд-ордеров на 20 матчей | **метрика интересности** |
| APM + доля отменённых команд | метрика «дёрганья» (гистерезис) |
| Доля нелегальных действий | должна быть ~0 после masking |
| Энтропия политики | падает в 0 → ИИ выродился в одну стратегию |

Плюс **инспектор реплея**: топ-10 записей по |reward| с причинами. Сразу увидишь, что буфер на 90% состоит из `no_base2` — это и есть диагноз reward drowning.
